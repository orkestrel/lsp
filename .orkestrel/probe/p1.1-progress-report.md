## The fixture mechanism the rows needed

The finding's condition is a `didClose` transport write that never settles. `LSPClient.close` awaits
`#write`, `StdioTransport.send` awaits `stdin.write`, and that callback fires only after the host
takes every byte, so the write is held exactly when the child's pipe is full. Two facts made that
buildable:

- `LSPClient.#openPush` awaits the `didOpen` write **before** it awaits the publication, so the open
  write has to settle. The document therefore has to fit the pipe while leaving no room for the
  close.
- A fixture that frames `initialize` through `readSync` on descriptor 0 owns no stream buffer, so
  after it stops reading, the only room left is the host's own pipe buffer. A fixture that pauses a
  flowing stream instead absorbs another chunk, and the usable band narrows to about two kilobytes,
  which is inside the measurement's own drift. The `stall` fixture therefore reads synchronously.

`readStallPayload` bisects for the size at which a close-sized follow-up write stops settling, then
returns that size plus eight kilobytes and confirms the reading reproduces. On this host, measured
2026-08-26, the turn lands at 127879 bytes and the returned payload is 136071 bytes, stable across
consecutive runs. The row skips with the measured reason on a host where the confirmation fails.
