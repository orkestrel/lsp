## Why the reorder starves nothing

I read the parking and release paths before moving the line. A parked consumer never coexists with a queued frame: the loop parks only after `shift()` returned `undefined`, and `#routeSubscription` resolves a present waiter directly rather than pushing (`src/core/MCPClient.ts:710-714`). So the parked-consumer terminal case is untouched — it resolves through `#settle`'s `waiter.resolve(value)` branch and returns from `else return frame`, never through the moved line. The drain terminates because `#settle` deletes the pending entry before setting `terminal`, so `#routeSubscription` finds no subscription and no further frame can enter the queue: the loop drains a fixed queue, then returns. Overflow and abort route through `#cancelSubscription` → `#settle(…, failed)`, which sets `queue.length = 0` and `failure`, so the failure branch still preempts with nothing left to drain. Late frames after settlement are unchanged.
