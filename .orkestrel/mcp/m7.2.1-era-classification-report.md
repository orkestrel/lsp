## Era ruling and derivation

The definitive legacy-evidence set at discovery is `JSONRPC_METHOD_NOT_FOUND` alone.

- `guides/mcp.md:82-90` assigns `2026-07-28` to handshake-free modern requests and assigns the
  supported `initialize` revisions to the legacy era.
- `guides/mcp.md:1622-1624` states that `MCPClient` contains no legacy handshake and sends only
  `server/discover`.
- `guides/mcp.md:1697-1704` assigns the dated handshake to
  `MCPLegacyClientTransport` and states that the bare client never attempts it.
- `guides/mcp.md:2895-2906` defines `connect()` as modern `server/discover` negotiation and directs
  legacy peers to the explicit adapter.
- `src/core/validators.ts:1236-1247` separates `isMCPModernVersion` from
  `isMCPLegacyVersion`; every supported `initialize` revision belongs to the latter guard.
- A `-32601` answer proves that the peer has no `server/discover` method. A `-32000` server-state
  answer, another JSON-RPC error, a rejected transport write, a network fault, or a timeout proves
  only the failure it reports.

The existing `MCP_UNSUPPORTED_VERSION` retry remains unchanged. An unpinned client retries only
when the peer's `supported` context contains a supported modern revision.
