## Scope

Owned: the failing test files named in Context; `src/server/` and `src/browser/` source
where a ruled genuine break requires a fix; `guides/mcp.md` only where a repaired
behavior's prose is now false. Off-limits: `src/core/` beyond what a ruled genuine break
strictly requires (M1 owns that design — a core change beyond mechanical stops the unit);
`package.json` version; every rename (M6 owns them); commits and pushes — the
Orchestrator commits.

## Execution

Perform this assignment directly yourself and spawn nothing. You run on the host: the
full suite, scoped projects, and single files are all yours to run. Use scoped runs while
iterating; run the complete `npm test` once at the end and read it.

## Output

Return, and nothing else: the per-test ruling table; what changed per file and why; the
end-state `npm test` summary line verbatim; the WebSocket single-file reading (both
commands and results); deviations or none; and the actual `git diff --stat` and
`git status --porcelain` output.

## Deviation contract

A ruling that requires changing `src/core/` design, a modern-era behavior M1's report
claims intentionally, or anything off-limits stops the unit: report expected, found,
evidence, done or not done, one short hypothesis. Ancillary choices (canary method
wording, test naming) are yours to decide and record.

## Acceptance criteria

1. Every test in the failing set is ruled in the table and its repair landed.
2. `npm test` in `/home/user/mcp` exits 0 on the host, with no test removed, skipped, or
   weakened to pass — an assertion updated to modern truth must still assert the reply's
   substance, not merely its arrival.
3. No new failure relative to the baseline run.
4. `git status --porcelain` shows only owned files.

## Review evidence

The actual `git diff --stat` and `git status --porcelain` output in the report, plus the
verbatim final suite summary.
