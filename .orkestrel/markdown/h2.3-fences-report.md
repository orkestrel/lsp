## Decisions I made and recorded

- **Placement of the `scanInlineSource` row.** `scanInlineSource` is a `helpers.ts` leaf whose
  mirrored suite is `tests/src/core/helpers.test.ts`, which this unit does not own. Between the two
  owned files, `parsers.test.ts` is the inline-phase file — it already covers `parseInline` and
  already imports `splitLines` — and the guide introduces `scanInlineSource` as the inline engine's
  offset-bearing entry point. The row sits there under its own describe block with a comment naming
  why. `parsers.test.ts`'s header comment names `collectTable` and `collectList` as the leaves
  covered elsewhere and stays true, so I left it unedited.
- **Reuse over duplication for the merged-output reading.** The second line of the fence at `:362-374`
  claims `undefined` for a fresh node returned for several inputs. `Markdown.test.ts:242-248` already
  asserts exactly that value for exactly that rule, so I named it rather than transcribing a sibling
  with a different fixture.
- **`projectHTML` rather than a second `@orkestrel/html` import.** `tests/setup.ts:157` already
  exports `htmlToMarkdown(parseHTML(html))` as one helper, which is the fence's own call chain.

## Observations, not closed by this unit

- **The `projectSpan` boundary rule at `guides/markdown.md:229` is out of the transcription set.** No
  fence in § Source provenance reaches `projectSpan`, and the rule's owning suite,
  `tests/src/core/helpers.test.ts`, is off-limits to this unit. Its parts are pinned there today:
  `helpers.test.ts:260-269` pins the zero-width abutment resolving through the later segment,
  `:243-250` pins `undefined` when a boundary misses every segment, and `:185-200` pins a projection
  across a recorded separator. The bridging clause — that `projectSpan` bridges an uncovered interior
  when both boundaries resolve — has no `projectSpan` row of its own; `:214-227` builds the uncovered
  interior but never projects across it. My probe measured the brief's bridge fixture as
  `0..3 -> { start: 0, end: 2 }`, `1..2 -> undefined`, `2..3 -> { start: 1, end: 2 }`, so the values
  a future row would assert are known. Carrier for the gap: a unit that owns `helpers.test.ts`.
- **Claim I flag for the analyst.** The `reports undefined for every node of a document projected in
  from HTML` row asserts more than the fence comment does — the fence names only the document, and
  the row asserts every node the walk yields. The addition is measured, not derived, but it is a
  wider claim than the fence carries and an auditor may want it narrowed to the fence.
