## Deliverable 1 — one home for the escaped-pipe rule (R6)

Before: `splitTableRow` in `src/core/helpers.ts` re-implemented the escaped-pipe splitting rule
`splitTableSources` already owns (a parallel character loop with its own `\|` handling).

After: `splitTableRow` derives from `splitTableSources`:

```ts

	return splitTableSources({ text: row, segments: [] }).map((cell) => cell.text)
}
```

The TSDoc description gained one sentence naming the derivation and the owning function.

**Executed proof of identical behavior** (throwaway `tmp/probe/splitTableRow.test.ts`, deleted
after the run): compared `splitTableRow(row)` against
`splitTableSources({ text: row, segments: [] }).map((cell) => cell.text)` over plain, escaped,
empty, and mixed-whitespace rows (`'|a|b|'`, `'a|b'`, `'| a\\|b |'`, `'||'`, `'|  |'`,
`'  |a| b |c|  '`, `'\\|leading|middle\\||trailing\\|'`). `1 passed (1)` — behavior unchanged for
every case, and the consumers `delimiterToAlignments` and `validators.ts:196` call `splitTableRow`
unaltered, so their observable behavior is unchanged too.
