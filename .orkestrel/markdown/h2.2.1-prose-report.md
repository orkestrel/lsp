## The corrections

### 1. The `MarkdownSegment` remark's zero-width bullet (`src/core/types.ts`)

Before (pre-edit content of the owned region):

```text
 * - a zero-width `p` that coincides with the next segment's `offset` resolves through
 *   that LATER segment, so a discontinuous abutment reports the later run's `start`
 *   rather than the earlier run's `end`.
```

After:

```text
 * - a zero-width `p` that coincides with a later segment's `offset` resolves through the
 *   LAST segment whose `offset` equals `p`, skipping every earlier segment at that
 *   position whatever its extent, so a discontinuous abutment reports that final run's
 *   `start` rather than the earlier run's `end`.
```

Readings it rests on. The supplied cascade reading, re-produced by this unit's probe through the
real `projectSpan` (`tmp/probe`, `@src/core` barrel):
`segments [{offset 0, start 0, end 1}, {offset 1, start 5, end 5}, {offset 1, start 9, end 10}]`,
`projectSpan 1..1 -> {"start":9,"end":9}`, `1..2 -> {"start":9,"end":10}`,
`0..2 -> {"start":0,"end":10}`. The immediately later segment starts at `5`, so "that LATER
segment" was false; `9` is the `start` of the LAST segment whose `offset` is `1`.

One further reading settled the wording, taken because the brief's phrase "skipping every
zero-extent run" names a property the code does not test. Over
`{ text: 'abc', segments: [{offset 0, start 0, end 2}, {offset 2, start 9, end 10}] }`,
`projectSpan 2..2 -> {"start":9,"end":9}`: the skipped predecessor is two units wide, so the skip
is driven by the successor's `offset` rather than by the predecessor's extent. The wording says
"whatever its extent" for that reason. `projectSpan` in `src/core/helpers.ts:236-241` reads the
same way: the `from === next.offset` guard continues past the current segment regardless of
`segment.end - segment.start`.

Control readings kept the bullet's other two rules honest:
`{ text: 'ab', segments: [{offset 0, start 0, end 2}] }` gives `2..2 -> {"start":2,"end":2}`
(derived end claims `end`, no later segment at that position) and `1..1 -> {"start":1,"end":1}`
(strictly inside, affine).

  own ordered `segments` array the algorithm answers through. It tallies nothing and names no
  prose list item; the file's accepted vocabulary already carries "the next segment's `offset`" and
  "the first part's `start` to the last part's `end`".
- `the range's two boundaries` and `when both boundaries resolve` — permitted. A range has exactly
  the `from` and `to` boundaries and that set cannot grow; the sentence naming `both` follows the
  sentence that names the members.
- `Own-region resolution runs first` — permitted. `first` orders a resolution step in time, not a
  list item by position, and the accepted guide prose already ships the same phrase.
- `every one of those cases` — permitted. `one` here is part of the quantifier, not a tally.
