## Sentence-by-sentence ruling over the enumerated population

### `MarkdownSpan` (`src/core/types.ts:38-54`) — CORRECTED

Was: "`markdown.slice(span.start, span.end)` returns the source the node was parsed from," which
reads as an identity between the slice and the node's value. Q1 falsifies it: the text node of
`'a \nb'` values `a\nb` and spans `{0,4}`, which slices `a \nb` including the space
`normalizeParagraphLine` trimmed. Q1b adds the escape case: value `a * b `, span `{0,7}`, slice
`a \* b `.

Now states that the slice is the ORIGINAL source region the node was produced from, that the region
carries the syntax the value drops and the characters normalization removed, and names the `'a \nb'`
reading as its worked case. Opener changed from the noun phrase "A half-open region…" to
"Addresses a half-open region…".

### `MarkdownSegment` (`src/core/types.ts:56-91`) — CORRECTED

Was: "a position `p` inside the run projects back to `start + (p - offset)`" plus "Every strip,
trim, and join the block phase performs is affine at this granularity." Q2 falsifies the affine
claim at a run's end boundary: on the CRLF-joined source the middle run is `{offset 1, start 1,
end 3}`, and `projectSpan(_, 1, 2)` returns `{1,3}` rather than the affine `{1,2}`.

Now states the boundary rule `src/core/helpers.ts:220-248` implements, as three cases: affine
strictly inside the run; `end` at the run's derived end, which is how the one-unit `\r\n` separator
run reports its two-unit region; and resolution through the LATER segment for a zero-width position
coinciding with the next segment's `offset`. Q2's abutment reading `{0,0,1} / {1,5,6}` →
`projectSpan(_, 1, 1)` = `{5,5}` pins the third case, which is the `h2.1-derive` fix's shipped
behavior. Opener changed from "One run of a …" to "Maps one run of a …".

### `MarkdownSource` (`src/core/types.ts:93-116`) — CORRECTED

Was: "`segments` cover `text`". Q3 falsifies it: joining `{text 'a', 0..1}` and `{text 'b', 1..2}`
with `'\n'` produces segments `[{0,0,1},{2,1,2}]` because `joinSources` records a separator segment
only where `left.end < right.start`, so derived offset 1 is uncovered and
`projectSpan(joined, 1, 2)` returns `undefined`.

Now states that the runs need not cover every position, names the fabricated-join case that leaves
a separator uncovered, and directs the reader to test coverage with `projectSpan` rather than assume
it. Opener changed from "A piece of derived markdown text paired with…" to "Pairs a piece of derived
markdown text with…".

### `MarkdownParseResult` (`src/core/types.ts:413-432`) — CORRECTED
