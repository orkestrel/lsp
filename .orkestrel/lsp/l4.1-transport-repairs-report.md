**2. Generation-scoped emission** — same file
- Mechanism chosen: **a generation guard on each emit**, with `#retire` as the single retirement point (`:203-224`). `#observe(child, generation)` captures the generation id; `#deliver`, `#report`, and `#retire` return before emitting when the captured id is stale.
- Reason for the guard over detaching listeners: detaching the `data` listener pauses the stream, so a pipe-holding grandchild would block on a full pipe. The guard drops the emit while the retired generation keeps draining.
- Unprompted-exit consequence: `#retire` advances `#generation` **before** emitting, so the first settlement to arrive — the host's `close` event or the bounded wait inside `#settle` — wins and every later listener is retired. `exit` therefore emits exactly once per generation, unprompted or closed.
- Boundedness: `#settle` calls `waitForClose(child, this.#grace)` only when the generation is still live (`:178`), then retires with the child's own terminal facts. `waitForClose` does not short-circuit on an already-closed child, so the liveness check is what keeps a killed child's close from costing a full `grace`.
