## Item 1 — lifecycle state machine

Defect: concurrent starts sent duplicate handshakes, shutdown and initialize deadlines sent cancel
notifications, document close had no lifecycle gate, and a dead transport generation still admitted
an exit write.

Red evidence: the shared red command failed `shares one handshake across concurrent starts`, `closes
after the bounded shutdown fallback`, and `does not write exit after the transport generation exits`.
The initialize-deadline control used this command:

```text
npx vitest run --config vite.config.ts --no-cache --reporter=verbose --project src:core -t "does not cancel an initialize request at its deadline|closes after the bounded shutdown fallback"
```

With cancel gating disabled, it exited `1` with `2 failed | 69 skipped`. Restoring the lifecycle
gate returned those rows to green.

Fix: `LSPClientLifecycle` is a tagged union over idle, starting, ready, closed, destroying, and
destroyed phases. The starting and destroying variants carry their shared promises. Public doors
and `#send` read that state. A failed handshake closes its transport before a later start begins a
fresh generation. The destroy state records peer exit so teardown does not write into a dead
generation. The close gate is covered as a lifecycle boundary row.

## Item 2 — diagnostics deadline and session state

Defect: push diagnostics could wait forever, a full report without `resultId` retained stale cache,
and result identifiers survived transport exit.

Red evidence: the shared red command failed `bounds a push diagnostic publication deadline`,
`clears a prior result id when a full report omits one`, and `drops diagnostic result ids across an
exited generation`.

Fix: push publications carry the same abort-signal deadline and centralized settlement cleanup as
requests. A full report without an identifier deletes its cache entry. `#clearSession` clears
capabilities, documents, decode state, and diagnostics at exit, handshake failure, and teardown.

## Item 3 — send settlement and null-id errors

Defect: a synchronous transport send throw escaped as a raw error and left its pending entry live.
A null-id JSON-RPC error response lost its server category and wire code.

Red evidence: the shared red command failed `settles a synchronous request send throw as closed`
and `surfaces a null-id error response with its server code`.

Fix: every client send site routes through `#send`, which gates lifecycle state and converts throws
and rejections into a coded closed error. Request settlement deletes its pending entry. A null-id
error emits a server error carrying the wire code; unreachable null guards were removed.

## Item 4 — teardown and transport seam

Defect: exit sends were unbounded, synchronous close throws escaped cleanup, and a close rejection
after the deadline became invisible after emitter destruction. The transport seam stated none of
its foreign-implementation obligations.

Red evidence: the shared red command failed `completes destruction after a synchronous transport
close throw`. The retained reviewer derivation identified the unbounded exit send and delayed close
rejection; `bounds an exit write that never settles` and `surfaces a delayed close failure before
destroying the emitter` execute those boundaries and pass after repair.

Fix: exit and close settlement use the configured deadline. Promise normalization catches a
synchronous close throw. Listener removal, session clearing, lifecycle completion, and emitter
destruction run in `finally`. A close rejection that settles before the deadline is emitted before
destruction. At the deadline, the client emits a coded timeout before destroying the emitter and
absorbs the later close outcome. This choice keeps destruction bounded while making the failed
close observable in the only interval where the emitter can report it. The interface TSDoc states
reject-not-throw, post-close false sends, and restart obligations.

## Item 5 — retained bytes and malformed parameters

Defect: retained chunks aliased caller memory, a remainder retained the delivered frame buffer, and
a known `Content-Type` parameter without `=` was ignored.

Red evidence: the shared red command failed `owns retained chunks across caller mutation` and
`refuses a Content-Type parameter without an equals sign`.

Fix: parser state copies delivered chunks and uses `slice` for a frame remainder. A malformed known
header parameter throws a framing error. Unknown header fields remain tolerated.

## Item 6 — suite repairs

Defect: correlation responses were indistinguishable, abort teardown was hidden by explicit caller
destruction, the method-literal artifact had no red proof, and the shutdown row required forbidden
cancellation.

Fix: correlation payloads carry distinct diagnostics; the abort row waits for client-owned
teardown; the unused method pin was deleted; the shutdown row refuses cancellation. Added rows
cover concurrent start, push silence, cache deletion, session reset, send faults, close faults,
dead-generation writes, generation restart, boundary splits, exact limits, and the close/publication
race.

## Item 7 — payload bindings and public parity

Defect: initialize and diagnostic payload literals were checked only as generic JSON-RPC records,
and `LSPHeader` named a superseded capability.

Fix: initialize capabilities, initialize parameters, and diagnostic parameters use `satisfies`
against their declared contracts. `LSPHeader` was removed. `guides/lsp.md` documents lifecycle,
transport obligations, and owned decode state without naming the removed symbol.
