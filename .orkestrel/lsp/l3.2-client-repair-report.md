# L3.2 client repair report

The retained L3.1 re-check findings are repaired in the working tree. This unit made no commit,
installed no dependency, and changed no off-limits file.

## Generation ownership and teardown state

Defect: a failed `#begin` call could release, clear, and close a later generation started from the
client's `exit` handler. The public `exited` field also named a fact that was false when teardown
started from `idle` or `starting`.

The in-suite regression row ran red before the implementation change:

```text
npx vitest run --config vite.config.ts --no-cache --reporter=dot --project src:core tests/src/core/LSPClient.test.ts -t 'completes a restart issued from the exit handler as a second generation'
```

Result: exit 1; `1 failed | 47 skipped (48)`. The restart rejected an `LSPError` coded `closed` from
`#send` while `transport.starts` had reached 2.

Fix: `LSPClientLifecycle` carries a monotonic numeric `generation` on `starting` and `ready`. A
`destroying` state retains that identity only when an initialized generation still owes the
protocol `exit` write. `#begin` checks the identity before the initialized write, before publishing
capabilities and `ready`, before release, and again after the awaited release. The numeric identity
is the smallest immutable value that lets an older asynchronous path compare ownership without
retaining transport objects or adding a second lifecycle flag.

The same command ran green after the fix: exit 0; `1 passed | 47 skipped (48)`.

Type-first observation: after only `types.ts` changed, this command settled implementation drift:

```text
npx tsc --noEmit -p configs/src/tsconfig.core.json
```

It exited 2 and reported missing `generation` members at the `starting` and `ready` assignments,
the removed `exited` member at construction and update sites, and the removed `exited` read. After
the implementation conformed, the command exited 0. The `prove` MCP instrument was unreachable in
this executor, so no `receipt probe:...` line exists. The compiler control for the host receipt is
the `starting` assignment without `generation`; it must fail at TypeScript with `TS2322` because
`LSPClientLifecycle` requires that identity.

## Publication drain

Defect: `#drain` rejected publications directly and cleared the map without detaching deadline
listeners. A stale deadline could then reject a publication for the same URI in a later generation.

The in-suite regression row ran red before the fix:

```text
npx vitest run --config vite.config.ts --no-cache --reporter=dot --project src:core tests/src/core/LSPClient.test.ts -t 'detaches a drained publication deadline before the next generation'
```

Result: exit 1; `1 failed | 47 skipped (48)`. The later publication rejected an `LSPError` coded
`timeout` from `#timeoutPublication`.

Fix: `#drain` iterates a snapshot of publication URIs and calls `#settlePublication`, which owns map
deletion, deadline-listener removal, and rejection.

The same command ran green after the fix: exit 0; `1 passed | 47 skipped (48)`.

Mutation probe: the routing line was replaced with direct rejection plus `#publications.clear()`.
The same command exited 1 with `1 failed | 47 skipped (48)` and the later publication rejected coded
`timeout`. Restoring the routing hunk byte-identically made the same command exit 0 with
`1 passed | 47 skipped (48)`.

## Initialization-window response

Defect: `#send` refused every response while the lifecycle phase was `starting`, so an unsupported
server request could stall the initialize exchange.

The in-suite regression row ran red before the fix:

```text
npx vitest run --config vite.config.ts --no-cache --reporter=dot --project src:core tests/src/core/LSPClient.test.ts -t 'answers an unsupported inbound server request during initialization'
```

Result: exit 1; `1 failed | 47 skipped (48)`. The fixture recorded only the initialize request and
not the method-not-found response.

Fix: `#send` permits a response, identified by the absence of `method`, during `starting`. It still
refuses non-handshake requests and notifications during that phase.

The same command ran green after the fix: exit 0; `1 passed | 47 skipped (48)`.

## Teardown bound and import order

Defect: the public teardown contract did not state how close failures interact with the deadline,
and the named type imports in `LSPClient.ts` were out of order.

The delayed-close regression command recorded in the re-bound rows is the behavioral red and green
for pre-deadline emission. The deadline behavior remains pinned by the existing close-deadline row
in the scoped suite. At the baseline,
`grep -h 'close outcome' src/core/types.ts guides/lsp.md | wc -l` reported 0. After the
documentation change, the same check reports 2.

Fix: the `destroy` TSDoc and guide state that a close failure settling before the deadline is
emitted before emitter destruction; at the deadline the client emits a coded `timeout` error and
absorbs the later outcome. The `LSPClientCapabilities` import precedes the remaining `LSPClient*`
type imports alphabetically.
