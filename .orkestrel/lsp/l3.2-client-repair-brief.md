## The findings, item by item

### Item 1 — generation identity (reconciled claim 1 and finding C)

`#begin`'s failure path (`src/core/LSPClient.ts:246-253`) guards only `destroying` and
`destroyed`, so a restart installed from inside the client's own `exit` handler is clobbered:
generation one releases the generation, clears the session, and overwrites generation two's
`starting` phase with `closed`. Ruling: a generation writes only lifecycle state it owns — carry
an identity the failure path checks before touching shared state, and a restart issued from the
exit handler completes a second generation. Suite row: adapt probe 1 from the retained
instrument onto the suite's own fixture, named for what it proves; red at `9c343cf` re-recorded,
green after.

Finding C folds in here: `LSPClientLifecycle`'s `destroying.exited` member is set true from
`idle` and `starting` (`:196-199`), where the fact its name states is false, while the consumer
(`:589`) reads "no exit write is owed". Name the member for the decision it carries or derive
that decision from the generation state you introduce, per the derive-state law. The type is
public: update `types.ts`, the TSDoc, and any guide row naming it.

### Item 2 — publication drain (reconciled claim 2)

`#drain` (`:553-557`) rejects publications directly and never detaches their deadline listeners,
so a drained publication's timer kills the next generation's publication for the same URI
(executed: probe 2). Ruling, adopted verbatim from the verdict: route the publication loop in
`#drain` through `#settlePublication`, so one method owns publication deletion and listener
detachment exactly as `#settle` owns them for requests. Because the prescription is verbatim,
close it with a mutation probe: after the fix, revert the routing hunk, run the new row red,
restore, run green, and record all counts. Suite row: adapt probe 2 onto the suite's fixture,
named for what it proves.

### Item 4 — the handshake-window response (finding A)

`#send`'s predicate (`:373-381`) refuses an outbound response during `starting`, so
