## Findings outside the claims

**A. `src/core/LSPClient.ts:489-509` no longer answers a server request during the handshake, reversing this round's own ruling.** `#respondUnsupported` writes a response, and a response carries no `method`, so `#send` computes `method === undefined` (`:374`) and permits it only in phase `ready` (`:376-381`). A server request arriving after the client wrote `initialize` and before the server answered it is therefore refused with `LSPError` coded `closed`, and the client emits an `error` instead of writing the response it wrote before this repair (diff `l3.1-diff.txt:422-444`).

Why it matters: the immutable reviewer verdict of this same round ruled that interleaving explicitly — "A server request arriving before `initialized` — safe; the client answers with a response, which the base protocol permits in that window" (`l23-audit-reviewer-verdict.md:101`). The lifecycle ruling was written to stop client-initiated traffic preceding the initialize result; it silently took a permitted server-initiated exchange with it, and `.claude/rules/quality.md` § Rounds and verdicts requires a seam ruling to carry the constraint that bounds it against exactly this over-correction. A peer that waits for the response before answering `initialize` now stalls until the initialize deadline, and the emitted code `closed` misdescribes a client that is starting. No row covers a server request outside `ready`; `tests/src/core/LSPClient.test.ts:717` drives it only in `ready`.

What right looks like: permit an outbound response in `starting` as well as `ready` in `#send`'s predicate, and pin a row that sends a server request between the `initialize` write and its result and asserts the method-not-found response reaches the wire.

**B. `guides/README.md` still declares `guides/lsp.md` uncreated, in both indexes.** The concept index (`guides/README.md:6-7`) and the directory index (`:18-19`, `:22-23`) each read "Not created. Create this file when the workspace has a public surface: `guides/lsp.md`", while the file now exists. `.claude/rules/documentation.md` makes that README the map and requires both indexes maintained, and `guides/scaffold.md:1234` places it among the template artifacts the workspace owns rather than among the vendored paths a repair restores, so nothing regenerates it. The fix unit's scope listed neither the README as owned nor as off-limits, so no carrier existed for the row the guide's creation falsified.

What right looks like: replace all three placeholders with links to `guides/lsp.md`, in a unit that owns `guides/README.md`.

**C. `LSPClientLifecycle.exited` asserts a fact that is false in the states that set it.** `src/core/types.ts:232` publishes `{ phase: 'destroying'; promise; exited: boolean }`, and `destroy()` sets `exited` true whenever the prior phase was `closed`, `idle`, or `starting` (`src/core/LSPClient.ts:196-199`). In `starting` the transport has been started and the peer is alive; in `idle` no generation exists at all. The single consumer reads it as "no exit write is owed" (`:589`), which is a different predicate from the one the name states, and `#receiveExit` sets the same field for the genuine meaning (`:562`). The type is exported through `src/core/types.ts` and star-exported by `src/core/index.ts:1`, so the next reader meets the misleading name on the public surface, and `AGENTS.md` § Design laws forbids storing a label that can drift from the fact it names.

What right looks like: name the field for the decision it carries, or derive that decision from a stored generation state so one field cannot mean two things.
