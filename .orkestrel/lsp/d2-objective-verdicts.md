1. **Rule the monolith honest.** Do not split `parseLSPMessages` into exported leaves. The function is the codec spine, not a bag of independent coercers: it chains owned segments, scans with a 3-byte overlap, joins only after a boundary exists or a body completes, refuses with `context.messages`, and re-seeds the remainder (`src/core/parsers.ts:33-286`, `src/core/types.ts:350-373`). Architecture keeps a defining engine when extraction would leave a thin sequencer (`architecture.md` leaf test / anti-hollowing). Every extracted declaration would have to be exported, barrelled, and tested (`architecture.md` kind purity; `src/core/index.ts` star-exports `parsers.js` and `helpers.js`). That publishes internal steps whose only consumer is this function (`src/core/LSPClient.ts:439-443`; `tests/setupServer.ts:117-125`). Inlined scan/header/join statements are legal; they become placement problems only once they are declarations. The duplicated join at `src/core/parsers.ts:102-110` and `:241-250` does not overturn this: those blocks are two lifecycle points of the same spine (do not flatten an incomplete header — `:88-94` returns the chain; body chunks re-chain onto a resolved node — `:43-50`, `:239`), and a public flatten would invite callers to collapse `LSPDecodeState` and break the constant-work append invariant (`src/core/types.ts:354-356`).

2. **No leaves.** Candidate seams, refused:

   - **Segment join** (`LSPDecodeState` → one `Uint8Array`). Not a `parse*` coercer. If extracted it would live in `helpers.ts` as a `{verb}{Noun}` (`architecture.md` one-directional naming). The alias when `previous === undefined` (`src/core/parsers.ts:102`, `:242`) and the size-offset copy (`:104-109`, `:244-249`) stay correct only inside the spine that decides *when* to join. Publishing it expands the framing surface beyond `encodeLSPMessage` / `parseLSPMessages` / `LSPDecodeState` (`guides/lsp.md:295-301`) with no external consumer.

   - **Boundary scan.** A lexical search, so `scan*` in `helpers.ts`, never `parse*` in `parsers.ts` (`architecture.md`: a `scan*` in `parsers.ts` is misplaced). The load-bearing part is not the four-byte compare (`src/core/parsers.ts:76-86`); it is the overlap window from the previous chain (`:59-74`) and `boundary = previousSize - overlap + index` (`:83`). Header-limit refusal uses `messages` and `pending.size` (`:88-100`) and must stay on the composer. `tests/src/core/parsers.test.ts:51-61` already binds every CRLF split offset. A `scan*` leaf is either a trivial loop (fold) or a decode-state helper whose tests would re-derive the algorithm (`tests.md`: do not assert an implementation against itself).

   - **Header parse.** Cannot be a `parse*` coercer. `parse*` is `T | undefined` and must not throw (`names.md` fixed forms). Collapsing faults to `undefined` drops bound context: over-limit `Content-Length` sets `context.value` (`src/core/parsers.ts:162-166`; `tests/src/core/parsers.test.ts:245-263`); unsupported charset sets `context.value` (`src/core/parsers.ts:206-213`); every header throw freezes accumulated `messages` (`src/core/parsers.ts:116-221`). `LSPClient.#receiveChunk` still dispatches those messages (`src/core/LSPClient.ts:444-448`). A throwing leaf that takes `messages` is not independently understandable; a refusal-union leaf needs a new public type. Either form is the wrong kind for `parsers.ts`. Refusal stays in `parseLSPMessages`.

   - **Message shape gate.** `parseJSON` is already the coercer (`src/core/parsers.ts:264-268`, `@orkestrel/contract`). The three `isJSONRPC*` guards already exist and `LSPClient` uses them for dispatch (`src/core/validators.ts:50-88`; `src/core/LSPClient.ts:461-470`). UTF-8 uses `TextDecoder` (`src/core/parsers.ts:255-263`); wrapping that is a forbidden platform wrapper (`architecture.md` wrapper test). The protocol throw with `JSONRPC_INVALID_REQUEST` stays on the composer (`src/core/parsers.ts:270-276`; `tests/src/core/parsers.test.ts:266-287`).

3. **Proof obligations (no code change).** Keep `tests/src/core/parsers.test.ts` unmodified: split/coalesced frames, caller-mutation ownership (`:38-48`), CRLF-offset splits (`:51-61`), remainder re-seed (`:122-141`), byte-sized body continuations (`:144-173`), and every `context.messages` / `context.value` fault (`:219-302`). Keep `tests/src/core/helpers.test.ts` unmodified (`encodeLSPMessage` only). `collectPeerMessages` and `#receiveChunk` keep calling `parseLSPMessages` as they do now. Afterward the complexity probe must still read `parseLSPMessages` at 60 and still be the only lsp function above the oxlint default of 20 (`.orkestrel/lsp/complexity-probe-results.txt` `lsp max=20` block). Do not add an `oxlint-disable` (forbidden). Fleet adoption of `complexity` is a successor brief, not a silent split.

4. **Not worth it now. Record this ruling.** Complexity 60 is a probe reading, not a gate: `.oxlintrc.json` does not enable `complexity`. The proofs that bind this codec are the unmodified parser suite plus client salvage of `context.messages`. Extraction cannot drop that 60 without moving the header-fault tree, and that tree cannot move without either losing error context or minting public leaves. Churn on this path is a correctness risk, not a style debt. The byte seam stays where ruling 3 already put it (`.orkestrel/lsp/plan.md`); the internal shape stays one function.
